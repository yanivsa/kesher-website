# תוכנית תחימת משימות אוטומציה לג'ולס (Jules Rollout Plan)

## 1. רקע ומטרה

ג'ולס (Jules) הוא סוכן אוטונומי מעולה למשימות ביצועיות מוגדרות וטכניות בקוד ובתוכן. עם זאת, בעולם של ייעוץ זוגי והדרכת הורים — תחומים הרגישים לאתיקה מקצועית, אמינות קלינית (E-E-A-T) ודיני הגנת הצרכן — **אסור בתכלית האיסור לאפשר לסוכן אוטונומי חופש יצירתי בלתי מבוקר**.

מסמך זה מגדיר את הגבולות הקשיחים (Strict Boundaries), המשימות המותרות והאסורות, גדלי המנות המומלצים, ושערי האימות (Gates) הנדרשים בכל הרצה של ג'ולס.

---

## 2. חלוקת משימות: מותרות מול אסורות

### משימות מותרות לג'ולס (Allowed Tasks - Mechanical Retrofits)
1. **עיצוב והוספת טבלאות השוואה (Markdown Comparison Tables):**
   - הוספת טבלה בעלת 3-4 עמודות המציגה הבחנות קיימות מתוך תוכן המאמר (לדוגמה: תסמין, אתגר, דרך פעולה).
2. **הוספת מדורי שאלות נפוצות גלויים (ללא סכמת `FAQPage` ספקולטיבית):**
   - הוספת תוכן שאלות ותשובות גלוי בעמוד מתוך תוכן קיים, אך ורק כמענה מועיל לקוראים אנושיים.
   - **כלל מחייב:** *"Visible FAQ content may be useful when it genuinely answers user questions. FAQPage structured data should not be added as an AEO tactic. Structured data should be maintained only when it has a clear supported SEO/semantic purpose."* אין להוסיף סכמת `FAQPage`.
3. **הוספת שדות AEO אופציונליים למאמרי בלוג קיימים ב-`posts.json`:**
   - הוספת `directAnswer` תמציתי (עד 60 מילים) המבוסס אך ורק על טקסט שכבר כתוב במאמר.
   - עדכון שדה `updatedAt` לתאריך המדויק של השינוי.
4. **רישות קישורים פנימיים מכני (Internal Link Insertion):**
   - הוספת קישורים מתוך רשימת העוגנים והנתיבים המוגדרים ב-`docs/aeo/internal-link-map.md`.
5. **בדיקות עקביות וסנכרון קבצי הפקה:**
   - הרצת `npm run generate` לסנכרון sitemap, RSS ו-llms-full.

### משימות אסורות בהחלט לג'ולס (Forbidden Tasks)
1. **אסור לנסח דעות קליניות או המלצות טיפוליות חדשות:** ג'ולס לא ימציא פרוטוקול טיפולי, שיטות הדרכה, או עמדות מקצועיות שלא נוסחו ישירות על ידי שירה.
2. **אסור להמציא מקרים קליניים (Case Studies) או תיאורי טיפול בדויים:** כל דוגמה חייבת לבוא מניסיונה של שירה בעילום שם מלא.
3. **אסור לשנות את הגדרת הישות, ההסמכה או התארים:** שום שינוי בקורות החיים, בהשכלה או בתארי שירה סהרוני (`#shira`).
4. **אסור להוסיף שירותים עסקיים חדשים או לשנות מחירונים:** רק שירותים הקיימים באתר.
5. **אסור לבצע שכתובים המוניים (Mass Rewriting):** אין לשנות את שפת המקור, הסגנון האישי או המבנה הכולל של 74 המאמרים בבת אחת.
6. **אסור למזג PRs באופן אוטונומי ללא סקירת אדם (No Autonomous Merging).**

## 3. מדיניות גודל מנות (Batch Sizing)

כדי לשמור על שליטה מלאה ולמנוע הידרדרות איכותית:
- **גודל מנה מקסימלי:** 5 עד 8 מאמרים לכל משימת ג'ולס (Batch Size: 5-8 URLs).
- **הפרדת ענפים:** כל מנה תיפתח על ענף ייעודי נפרד (לדוגמה: `aeo/batch-couples-1`, `aeo/batch-gifted-1`).
- **ללא ריצות מקבילות מתנגשות:** מנה חדשה תתחיל רק לאחר שהמנה הקודמת נבדקה, אושרה ומוזגה לענף הראשי.

---

## 4. שערי אימות ובקרה אוטומטיים (Gating Criteria)

כל PR שנוצר על ידי ג'ולס חייב לעבור 100% משערי הבקרה הבאים בטרם יוצג לסקירת אדם:
1. `npm run generate` — סנכרון מלא של תקצירים, sitemap, llms-full ו-RSS.
2. `npm run lint` — אפס שגיאות lint בקוד ובסקריפטים.
3. `npm run test:content` — מעבר מלא של ולידציית התוכן ב-`scripts/validate-content.cjs` (בדיקת אורך, כותרות, תאריכי ISO, והיעדר תבניות דמה).
4. `npm run test` — מעבר מלא של בדיקות ה-Vitest כולל `aeo-foundation.test.ts`.
5. `npm run build && npm run verify:dist` — בנייה מוצלחת של כל הנתיבים ווידוא היעדר כפילויות תגיות.

## 5. צ'קליסט סקירה אנושית לפני מיזוג (Human Review Checklist)

לפני אישור ומיזוג PR של ג'ולס, הבודק האנושי (הבעלים / ארכיטקט ראשי) יוודא:
- [ ] האם ה-`directAnswer` נאמן לחלוטין לתוכן המקורי של המאמר?
- [ ] האם הטבלאות ברורות, קריאות במובייל ואינן שוברות את עיצוב העמוד?
- [ ] האם הקישורים הפנימיים טבעיים ומובילים לנתיבים קיימים ותקינים?
- [ ] האם שדה `updatedAt` מוגדר לתאריך האמיתי ולא עודכן סתמית בכל המאמרים?
- [ ] האם אין שום זכר לטענות טיפוליות מנופחות או סופרלטיבים בלתי מבוססים?
