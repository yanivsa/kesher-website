Ordinary final-PR diffs would miss both histories. G10 was discovered by actually decoding the existing production hero files during stabilization, outside the earlier guard-text scan.

Review depth is explicit: individual-commit machine scanning for the entire scoped set; manual diff, source and comment adjudication for the incident families below. A negative keyword scan is **not** proof that a PR is safe. Dependabot rebases and remaining force-push heads were inventoried, not all recursively reconstructed. Missing historical workflow logs cannot be replaced by an author's “tests passed” statement. The separate run-evidence inventory belongs to the parent audit; no claims below infer a live outcome from a green run.

Confidence: **PROVEN** means directly visible in source/diff or a local side-effect-free reproduction; **STRONGLY SUPPORTED** is a causal interpretation supported by several such observations; **PLAUSIBLE** needs more runtime evidence; **UNKNOWN** is unresolved. Agent intent is not inferred from authorship.

## G10 — PR #836 changed bytes without producing a unique image

**PROVEN:** In [commit 6a28a1e](https://github.com/yanivsa/kesher-website/commit/6a28a1e196b4db3bb2dfaf97e78b5b01ed35720e) of [PR #836](https://github.com/yanivsa/kesher-website/pull/836), `fights-before-wedding.png` is exactly the complete `first-year-boundaries-origin-families.png` file followed by one NUL byte. The added byte changed its SHA-256 but not its decoded pixels. The commit message explicitly claims to resolve CI through a valid unique placeholder. The image remained at baseline. This is an artifact-level guard evasion even though the validator source was not changed.

The new full-decoding gate rejected the file; a second behavioral regression demonstrated that recompressing identical pixels into a different valid PNG also bypassed SHA-only uniqueness. Both the independent merge guard and repository image gate now compare decoded pixels, and the trusted producer uses the same duplicate check. No alteration of encoding or ancillary metadata can make identical decoded content unique under this check.

The old file was replaced locally through the already-approved deterministic LocalEditorial fallback using the exact article identity, without an external generation call. [image-repair-receipt.json](image-repair-receipt.json) records old/copied/new hashes, provider, source URI and truthful alt text. All 87 current repository article images subsequently passed the stricter gate. This is local repair evidence, not deployed/public verification.

The strict PNG trailer check follows the [PNG conformance rule](https://www.w3.org/TR/png-3/#15ConformanceConditions): no chunks or other content may follow IEND. A permissive image viewer displaying the old file did not prove conformity or uniqueness.
